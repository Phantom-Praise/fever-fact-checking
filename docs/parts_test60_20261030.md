# Sixty-claim paired test study

The user approved 60 fresh eligible test claims (20 per FEVER label) to fit a
3–4 hour project window. This replaces the proposed multi-day full-partition
evaluation for the present assignment. The 13,448-claim eligibility audit remains
available; it is not a completed evaluation.

Main: selected original essential-parts prompt over passages from a temporary
full-article Wikipedia RAG database. Baseline: frozen evidence RoBERTa, original
five-sentence input and 256-token combined input budget. Both classify the same
frozen 60 claims. No model is trained or downloaded.

## Execution

Use the existing virtual environment from the repository root. Preparation has
already created `reports/part2/parts_test60_20261030_v2`; do not prepare over it.

```sh
# Resume the existing run; completed predictions are skipped.
.venv/bin/python src/experiment_parts_test.py run --output reports/part2/parts_test60_20261030_v2

# Only after all 60 paired predictions exist:
.venv/bin/python src/experiment_parts_test.py score --output reports/part2/parts_test60_20261030_v2

# Read-only progress and full traces:
.venv/bin/python src/serve_parts_test.py --run reports/part2/parts_test60_20261030_v2 --port 8766
```

Viewer: http://127.0.0.1:8766/ . Gold labels and accuracy stay out of the running
dashboard until explicit final scoring. Exact prompts/responses and source
excerpts remain available. The viewer never runs the model.

The runner records source/model/embedding and data hashes, CPU baseline setup,
Llama tokenizer calibration, per-stage times, fetch coverage and workspace
deletion. It uses a process lock and exclusive atomic writes. Crash recovery
keeps completed conditions and records new attempts only for unfinished claims.
It refuses changed source hashes or model/runtime versions. Do not edit frozen
sources to fix a particular test answer.

The first prepared run crashed in the native OpenMP runtime while loading
RoBERTa, before saving any test predictions. Its artifacts are retained in the
original `parts_test60_20261030` folder. Version 2 isolates RoBERTa in a process
that does not import FAISS, avoiding the two OpenMP runtimes sharing that
inference process. The 60 input IDs/order, prompts and model settings are
identical between the prepared versions. This is an engineering repair before
observing test predictions, not prompt tuning from test outcomes.

The exact tokenizer adapter currently uses the pinned local macOS Ollama server
and its model blob path through the preserved calibration helper. This is a
machine-specific implementation. Missing/changed tokenization fails explicitly;
it never assumes that the whole context fit or silently drops passages.

The existing Python environment was extended with matplotlib 3.9.4 and its
plotting dependencies to produce assignment figures. No existing model package
was retrained or model weights downloaded. The installation log is under
`output/plan_parts_test_20261030/plot_dependency_install.log`.

## Interpretation

The hypothesis frozen in the protocol is that the main pipeline improves both
accuracy and macro-F1 over evidence RoBERTa on these paired claims. Report its
outcome even if negative. The model's overall label is diagnostic; the primary
prediction is deterministically derived from the validated part verdicts.
INVALID answers remain in the denominator and get a separate confusion-matrix
column. All test failures remain in the saved results.

This is a balanced, small, single-run sample. It does not estimate natural
class-prevalence accuracy without qualification. Prompt selection was based on
other development cases. Current Wikipedia differs from historical FEVER; live
article block IDs cannot be used to compute strict FEVER evidence scores.
RoBERTa's historical gold-evidence/empty-NEI training shortcut remains a baseline
limitation. Changes in the complete pipeline prevent attributing a difference
to the vector database or prompt alone.

Generated qualitative examples are selected from paired correctness groups.
They support inspection, not an independently annotated error taxonomy.
The ten-case 7/10 development result is not pooled into this test result.

## Completed measurement

All 60 paired claims finished. Main: 38/60 (63.33%), macro-F1 0.6583, including
four INVALID output-limit failures. Baseline: 34/60 (56.67%), macro-F1 0.4548.
The paired accuracy difference is +6.67 percentage points with a bootstrap
interval of -10.00 to +21.67 points. NEI recall improved from 0/20 to 12/20;
SUPPORTS and REFUTES recall declined. The hypothesis is partially supported;
a reliable general accuracy improvement is not established.

Every submitted main-model prompt passed the exact-token check. All 60 temporary
workspaces were deleted. Seven claims had a recorded article-fetch error but
still had usable article context. Correct labels sometimes had unsupported
justifications; see the qualitative review. The original 19K Llama run remains
stopped, and no model was retrained or branch merged.
